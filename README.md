# dosv_emu_cpp

**DOS/V** を名乗るところまで作った、C++17 の MS-DOS エミュレータです。
[dos_emu_cpp](https://github.com/yomei-o/dos_emu_cpp) から分けたもので、
向こうがコンパイラ（LSI C-86 / DJGPP / Watcom）を動かすことを目指しているのに対し、
こちらは **DOS/V の日本語環境で動くグラフィックアプリ**を動かすことを目指しています。

最初の目標は **ＪＷ＿ＣＡＤ for DOS/V** です。
[jwcad_dos_wasm](https://github.com/yomei-o/jwcad_dos_wasm) が同じ CAD を
逆コンパイルして C に書き直していて、**その移植が正しいかを、ここで動かした本物と
画面で突き合わせて確かめる**——というのがこのリポジトリの存在理由です。

## いまどこまで

`JW_CADV.EXE`（1.45 MB、Microsoft C 6.0、オーバーレイ 36 個）が
**起動して、メニューを描いて、マウスとキーに応えて、図面を読んで描いて、
線を引いて、保存して、プロッタ出力まで出します。**
日本語入力（FEP）も、時計も、プリンタポートもあります。

```sh
export PATH="/c/prog/tools/w64devkit/bin:$PATH"   # このマシンには PATH の通った gcc がない
sh build.sh
mkdir -p tmp
./dosemu --root ../jwcad_dos_wasm/orig \
         --font-ank  ../jwcad_dos_wasm/font/JWANK16.FNT \
         --font-kanji ../jwcad_dos_wasm/font/JWKAN16.FNT \
         --script scripts/startup.txt \
         ../jwcad_dos_wasm/orig/JW_CADV.EXE
```

`tmp/01_startup.png` が起動画面、`03_click.png` が左ボタンで開いた上段メニューです。
図面を出すなら、ファイル名をコマンドラインに渡して:

```sh
./dosemu ... --script scripts/drawing.txt \
         ../jwcad_dos_wasm/orig/JW_CADV.EXE SAMPLE1.JWC
```

`tmp/drawing.png` に木造平面図が出ます。左上に要素数（線 762 / 円・文字 24）、
左下にレイヤのボタン、ステータス行に `S=1/100` `A-4` `表示倍率 0.57`。

## ブラウザで動きます

**<https://yomei-o.github.io/dosv_emu_cpp/>** —— 移植ではなく、
**1999 年の実行ファイルそのもの**がブラウザの中で動きます。

```sh
sh tools/build_wasm.sh     # dosemu.js + dosemu.wasm（本体 2.5MB、guest 同梱）
python -m http.server      # index.html を開く
```

エミュレータは **Web Worker** の中で回ります。ゲストは本物のプログラムで、
起動画面を出すまでに 4000 万命令ほど必要ですし、押しに応えるのにも 2000 万命令
かかります。ページを滑らかに保てるほど細かく刻むと、そのぶんゲストが進まない
——なので時計を worker に持たせ、画面が変わったときだけ送るようにしてあります。

`orig/` の JW_CAD 一式とフォントは `--embed-file` で .wasm に焼き込んであるので、
サーバもアップロードも要りません。

**ネイティブ版と 1 バイトも違わないことを検査しています** ——
`sh tools/wasmcheck.sh` が同じ台本を両方に流して 640x480 を `cmp` で比べます
（起動画面・作図・読取・日本語入力の 4 件）。2 つのフロントエンドは
エミュレータ本体を 1 行も違えず共有しているので、画面が違ったらそれは
フロントエンドの間違いです。

ページの上には **ＰＤＦ** と **ＰＮＧ** の釦があります。下の
「プロッタ出力から PDF と PNG」を読んでください。

**図面の出し入れもできます。** ゲストのディスクにある `.JWC` と `.DXF` が
ページの一覧に出るので、選んでダウンロードできます（JW_CAD の中で
入出力 → ①ファイル → ⑥ＤＸＦ → ① 保存 と書いたものも）。手元のファイルを
アップロードすれば、ゲストからは `A:\` のファイルとして見えます。

[RESUME.md](RESUME.md) に続きがあります。

## プロッタ出力から PDF と PNG

[dosbox_wasm](https://github.com/yomei-o/dosbox_wasm) と同じことを、
本物の JW_CAD にさせています。**エミュレータが絵を描くのではなく、
JW_CAD 自身にプロッタ向けの線を吐かせて、それを PDF と PNG にします。**

JW_CAD の中での道筋はこうです。

1. 画面左のメニューのいちばん下 `入出力`
2. 上の行の `②プロッタ`
3. 上の行の `③ﾌｧｲﾙ出力`（プリンタポートではなくこちら）
4. 出てくる一覧から `WASM.JWP` を選んで `①選択確定`
5. `出力ファイル名 ?` に `PLOT` などと打って [Enter]
6. `①確定` → `① 実行`
7. 「作図処理中」の数が 0 になるまで待つ
8. ファイルの一覧に出てきたら、ページの **ＰＤＦ** か **ＰＮＧ**

`plot/WASM.JWP` がその鍵です。JW_CAD の**プロッタ定義ファイル**
（書式は `orig/JWP.DOC` にあります）で、本物のプロッタの言葉（HP-GL）の
代わりに、読みやすい 1 行 1 命令を書かせます。

```
unit_x=100
MOVE  =M [1] [2]
DRAW  =D [1] [2]
ANK   =A [1] [2] [3] [4] [5]
KANJI =K [1] [2] [3] [4] [5] [6]
```

`plot.js` がそれを読んで、PDF（ベクタのまま。日本語は PDF 内蔵の
CJK フォント `90ms-RKSJ-H` に渡すのでフォントを埋め込みません）と
PNG（canvas で描いて `toBlob`）にします。用紙は中身に合わせます（周囲 10mm）。

**時計が要ります。** プロッタ出力の最中、JW_CAD は `INT 21h AH=2Ch` で
時刻を読んで進み具合を出します。ここが定数を返すと `残数( 122 )` のまま
止まって見えます。仮想の時計を入れてあり（`Dos::clock_per`）、
WASM 側は `_de_clock(20000)` で 2 万命令に 1/100 秒の割で進めます。

コマンドラインからも試せます。

```sh
sh tools/plotrun.sh                       # 本物に書かせる（既定は SAMPLE0）
DRAWING=TEST6 sh tools/plotrun.sh
node tools/plotpdf.mjs tmp/proot/PLOT.PLT tmp/plot/out   # out.pdf ができる
sh tools/plotwebcheck.sh                  # ページの釦ごと通しで検査
```

### ひととおり通してみる

```sh
sh tools/flowcheck.sh            # 起動 → 図面を読む → 保存 → プロッタ出力 → PDF → PDF を読む
```

**1 回の走行でぜんぶ**やります。部品ごとの検査（`savegrab.sh`・`plotrun.sh`・
`plotwebcheck.sh`）はどれもプログラムを起動し直すので、「開いて、保存して、
**その続きで**プロッタに出す」が通ることは言えません。保存のあとプログラムは
入出力 の中にいて、そこから ②ﾌﾟﾛｯﾀ に行けるかどうかは別の話だからです。

最後の PDF は `tools/pdfread.mjs` で**読み直します**。これは `plot.js` を
いっさい知りません——ビューアと同じように `startxref` から相互参照表を辿り、
表の各行が本当にそのオブジェクトを指しているか、ストリームの `/Length` が
実長と合っているか、`/Root` からページに辿り着けるか、文字が使う
フォントがページの資源にあるかを見ます。ここが狂った PDF は「開けるビューアと
開けないビューアがある」ものになり、書いた側では気づけません。
そのうえで、読み取った線と文字を**本物が書いた `.PLT` と突き合わせます**
（`tools/plotvspdf.mjs`）。

同じ `.PLT` を移植側と突き合わせる道具が
[jwcad_dos_wasm](https://github.com/yomei-o/jwcad_dos_wasm) の
`tools/plotcmp.py` です。円弧のない図面なら**本数も座標も一致**します
（SAMPLE0 11 本、TEST5 40 本）。

## 操作を流し込む —— `--script`

窓のないグラフィックアプリには「いま」がありません。画面比較は
**操作の並び**を両側で同じに再生できて初めて成り立つので、走らせ方を
スクリプトに書けるようにしてあります。時計は**命令数**です（実時間だと
マシンの混み具合で 2 つの走行の位置がずれるし、合わせる先がない）。

```
wait 13000000
mouse 300 200
click L
key esc
type ABC
shot tmp/01.png
```

## 本家から足したもの

どれも JW_CAD 固有ではなく、DOS/V のグラフィックアプリ一般に要るものです。

### BIOS データエリア（`0040:0000`）

プログラムは画面の寸法を BIOS に尋ねず**直接読みます**。空のままだと中立では
ありません——JW_CAD は画面の横幅を `0040:004A` から、文字セルの高さを
`0040:0085` から取って、**それで割ります**。0 のままだと
`run-time error R6003 - integer divide by 0` で、何も描かずに止まります。

### ビデオ BIOS（`INT 10h`）

「受けて無視」では足りません。JW_CAD はいまのモードを `AH=0Fh` で取って
終了時に戻すために覚え、`AH=00h` で自分のモード（既定は `12h`）にし、
そのあと上の BIOS データエリアを読みます。モード設定で桁数・行数・セル高を
書き換えるところまでやって、はじめて筋が通ります。

### DOS/V のフォント（`INT 15h AX=5000h`）

**DOS/V のプログラムは字形を持っていません。** ディスプレイドライバに
「字形を写すルーチンのアドレス」を尋ね、それを呼びます。JW_CAD は起動時に
2 回尋ねて（16×16 の漢字と 8×16 の ANK）、`ES:SI` に格納先、`CX` に文字コードを
入れて呼び出します。

返すのは `F000:FF00`（ROM BIOS 領域）に置いた 3 バイトの本物のコード——ここへ戻ってくる `INT` と
`RETF` です。写す中身は C++ 側が **FONTX2**（DOS/V のフォント形式）から引きます。

```
--font-ank  8x16 の FONTX2
--font-kanji 16x16 の FONTX2
```

これが無いと、JW_CAD が持つ関数ポインタはゴミのままで、最初の 1 文字を
描こうとした瞬間に `R6003` になります。フォントを外から渡す形にしてあるのは、
**移植側とまったく同じフォントファイルを両方に使わせる**ためです。
字形が違えば画面の比較に意味がありません。

### マウス（`INT 33h`）

**JW_CAD はマウスの有無を訊いているのではなく、要求しています。**
オーバーレイ 8 が機能 0（リセット）を呼び、AX が 0 で返ると画面モードを戻して
「ﾏｳｽﾄﾞﾗｲﾊﾞｰが組み込まれていません」と出して `exit(1)` します。
660 万命令ぶんの読み込みを全部やったうえで、何も描かずに終わります。

実装したのは 0（リセット）/ 1,2（カーソル）/ 3（位置とボタン）/ 4（位置設定）/
5,6（押下・解放の回数）/ 7,8（範囲）/ 0B（移動量）/ 0C（ハンドラ）。
**押下と解放は「回数」で数えます**——JW_CAD は機能 5/6 の回数を見るので、
ポーリングの隙に起きたクリックも拾われないといけません。

### 色（`INT 10h AH=10h`）

JW_CAD は `JW_PAL.DAT` を読んで、**自分のパレットを入れ直します**
（`AX=1010h` で DAC 16 本、`AX=1000h` でアトリビュートパレットを恒等に）。
EGA の既定とは別物で、4 は赤ではなく緑、6 は茶ではなく黄、7 は明灰ではなく白、
2 の赤は 0x3C です。受けて無視すると、画素が全部合っていても**色だけ違う絵**が
出てきて、画面比較の意味が無くなります。

6 ビットから 8 ビットへは上位ビットの複製（`(v<<2)|(v>>4)`）で、
`0x3F -> 0xFF`、`0x2A -> 0xAA` がちょうど出ます。移植側も同じ規則にすること。

## 本家との関係

`src/` は [dos_emu_cpp](https://github.com/yomei-o/dos_emu_cpp) のものが土台です
（8086/80386 の解釈実行、`INT 21h` の DOS 層、MZ/COM ローダ、DPMI ホスト、x87）。
そちらの経緯と設計は向こうの README に書いてあります。

**シフトとローテートがオーバーフローフラグを立てていなかったのは、
その土台から引き継いだ穴です。向こうにも同じものがあります。**
`shl`/`rcl`/`jno` は仮数を正規化する定石なので、ソフトウェア浮動小数点を
使うプログラムは軒並み踏みます——そして「失敗した」とはどこにも出ず、
計算結果だけが静かに変わります。
