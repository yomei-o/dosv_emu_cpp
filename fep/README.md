# 日本語入力 FEP —— 集めたもの

DOS/V のアプリケーションは日本語変換を自分ではやりません。JW_CAD は DOS から
1 バイトずつ読んで（`INT 21h AH=07h`）、返ってきたものを描くだけです。ローマ字を
かなにするのも、かなを漢字にするのも、候補の窓を描くのも、**FEP** —— コンソールに
割り込む常駐プログラム —— の仕事で、JW_CAD にはその **on/off 制御しか** 入って
いません（岩元明さんの「汎用FEP制御ライブラリ」FEPCTRL を使っています。バイナリの
`DS:0x1514` に `FP$PC98A` `FP$VJE` `FP$ATOK6` `MS$KANJI` …という検出テーブルが
そのまま残っています）。

つまり **変換窓を描く本体は配布物に入っていません**。合わせる相手を探して、
ここに置いてあります。どちらも Vector で今も配布されているフリーソフトです。

| ファイル | 中身 | 出どころ |
|---|---|---|
| `SKK-JISYO.L` | **かな漢字変換の辞書**（SKK Development Team、EUC-JP、約 16 万語）。`src/ime.cpp` がこれを読んで変換します。**GNU General Public License v2 以降**——ファイル先頭の著作権表示とライセンス条項をそのまま残してあります。 | <https://github.com/skk-dev/dict> |
| `otri055.lzh` | 日本語入力デバイスドライバ **「鳳」(おおとり) 0.55** —— べんぜん＝村田和久 氏、1994-05-07、フリーソフト。`OTRI.SYS` 本体＋全アセンブラソース＋**DOS/V 版**（`DOSV.LZH` の中）。 | <https://www.vector.co.jp/soft/dos/writing/se004462.html> |
| `wxpdosv4.lzh` | **wxpdosv 0.04** —— たかぴゅう(林孝之) 氏、1999-06-03、フリーソフト。エー・アイ・ソフトのフリー FEP **「WXP for J-3100」を DOS/V で動かすための TSR**。J-3100 固有の BIOS コールをエミュレートする 1 KB ほどの常駐プログラムで、**WXP 本体は入っていません**。 | <https://www.vector.co.jp/soft/dos/writing/se105856.html> |

中を見るには、対になっているリポジトリの LZH 展開ツールが使えます:

```sh
python ../jwcad_dos_wasm/tools/lzh.py fep/otri055.lzh          # 一覧
python ../jwcad_dos_wasm/tools/lzh.py fep/otri055.lzh out/     # 展開
```

## WXP for J-3100 —— 本物の FEP。ただしリポジトリには置けません

エー・アイ・ソフトが J-3100 用に配ったかな漢字変換 FEP。**`wxpj31.lzh`（540,762
バイト）を見つけて中身を確かめました**——SRA の ftp からは消えていましたが、
Wayback Machine に 2022-10-25 の控えが残っていました。

```
INFO.WXP  JISHO01.DIC(607,232)  JISHO02.DIC(43,008)  MANUAL.WXP  README.WXP
TENSAI.WXP  UWXP.EXE  WXADDDIC.EXE  WXDP.SYS(19,223)  WXP.SYS(91,648)  ...
```

標準辞書 10 万語（8 万語登録済み）、熟語 1 万 4,500、連文節変換・自動節変換・
逐次変換・単文節変換・コード変換、単語学習と文節学習——**本物です**。

**ただし、このリポジトリには入れていません。** 同梱の `README.WXP`（「エー・
アイ・ソフト（株）からのお願い」）にこうあります:

> 4. 利用者を含め、何人も WXP、WXDP 及び辞書の全部若しくは一部を有償で他に
>    提供・配付・販売・貸与することはできません。
> 5. WXP、WXDP 及び辞書の全部または一部を他のネットなどに転載することは、
>    エー・アイ・ソフト（株）の許諾なくできません。

自分の機械で使うのは無償で構わない（条項 2）、知人に手渡すのもこの文書を添付
すれば構わない（条項 3）——けれど**ネットに転載するには許諾が要ります**。GitHub に
置くのは転載にあたるので、`fep/local/`（`.gitignore` 済み）に置いて手元だけで
使っています。「鳳」と wxpdosv がフリーソフトなのとは条件が違います。

取ってくるには:

```sh
curl -sSL -o fep/local/wxpj31.lzh \
  "https://web.archive.org/web/2016id_/ftp://ftp.sra.co.jp/pub/os/msdos/utility/wxp/wxpj31.lzh"
python ../jwcad_dos_wasm/tools/lzh.py fep/local/wxpj31.lzh fep/local/wxp/
```

`-lh1-`（一九八八年の可変ハフマン方式）なので、展開には対のリポジトリの
`tools/lzh.py` が要ります——そのために書き足しました。13 ファイルすべて CRC 一致。

### いまどこまで動くか

`--device` でデバイスドライバを読めるようになりました（`src/device.cpp`）。

```sh
./dosemu --root DIR   --device "WXP.SYS /R /Z /H10 /CS /D1A:\JISHO01.DIC /D3A:\JISHO02.DIC"   --device "WXDP.SYS"   --font-ank ... --font-kanji ... JW_CADV.EXE SAMPLE0.JWC
```

```
dosemu: WXP.SYS:  installed CON      at 01FC:0000, 7808 paragraphs
dosemu: WXDP.SYS: installed  AISoft  at 184D:0000, 1197 paragraphs
```

**一九九〇年の WXP が組み込まれます。** 辞書 65 万バイトを読んで CON になり、
その上で JW_CAD も普通に立ち上がります。ただしキーはまだ正しく通りません
——WXP は J-3100 の BIOS を見に行くので、wxpdosv がその橋渡しをする必要が
あります。そして wxpdosv は「デバイスとして組み込んだ上で、もう一度
プログラムとして起動してください」というものなので、TSR が要ります。

### 動かすには何が足りないか

バイナリを読んで分かったこと:

* **`WXP.SYS` は `CON` デバイスドライバ**です（属性 `8013h`、名前 `CON     `、
  `A.I.Soft,Inc.   WX` の文字列つき）。つまり入力を割り込みで横取りするのではなく、
  **コンソールそのものに成り代わって** DOS のコンソール入出力を受け取ります。
* `wxpdosv` は `WXP$DOSV` という名前のデバイスドライバ兼 TSR で、
  **`INT 60h`（J-3100 固有 BIOS）** を立て、`INT 16h`/`INT 10h`/`INT 15h` を
  フックし、`INT 6Ch` で WX の状態を読み書きします。J-3100 の
  `INT 60h AH=0Ch`（システムライン数の設定＝FEP が使う行）を DOS/V の
  `INT 10h AH=1Dh` に読み替えるのが仕事の中心です。BIOS ワークの
  `0040:0417`（シフト状態）`0450/0451`（カーソル）`044A`（桁数）`0484`/`04D4`（行数）
  も使います。

このエミュレータに足りないのは四つ:

1. ~~**CONFIG.SYS のデバイスドライバ読み込み**~~ —— できました（`--device`）。
2. ~~**コンソール入出力を CON チェーン経由にする**~~ —— できました。AH=07h は
   CON ドライバへの READ 要求になり、AH=0Bh は非破壊読み出しになります。
3. ~~**DOS/V のテキスト画面**~~ —— できました（`src/text.cpp`）。`INT 10h`
   `AH=09/0A/0E/13` を FONTX のグリフで描き、`AH=13h` は DOS/V の拡張つき
   （AL のビット5＝文字と属性が交互、ビット4＝画面から*読む*）。`AH=1Dh` の
   システム行も入れました。
4. ~~**TSR**~~ —— できました（`INT 21h AH=31h` と `--run`）。

なお JW_CAD の検出テーブルには `FP$WXP` がありますが、この WXP は自分を `CON` と
名乗るので、その名前では引っかかりません（`FP$WXP` は後の WX 系のものでしょう）。
検出されなくても**入力そのものは通ります**——コンソールを通るので。

## 「鳳」は JW_CAD の上で動いています

`config.sys` に `device=otri.sys` と書いて組み込むデバイスドライバです。

```sh
python tools/mksmsdic.py fep/SKK-JISYO.L DIR      # 辞書を作る（一度だけ）
./dosemu --root DIR --device "DIR/OTRI.SYS /dA:\\" \
         --font-ank ... --font-kanji ... DIR/JW_CADV.EXE SAMPLE0.JWC
```

```
dosemu: OTRI.SYS: installed CON      at 01FC:0000, 1565 paragraphs
```

JW_CAD の文字列入力で **変換** キー（BIOS のキー語 `0B2FFh`）を押すと「鳳」が起き、
画面の右下に「鳳」が出ます。`yama` と打てば入力行に「やま」、**SPACE** で仮想鍵盤が
開いて「山」「岾」が並び、`1` を押すと「山」が JW_CAD の文字列に入ります。
一九九四年の FEP が、一九九九年の CAD の上で、窓ごと動いています。

分かったことを三つ:

* **OTRI.SYS は DIET 圧縮**です。ディスク上のオフセット 0 にあるのは展開ルーチンの
  デバイスヘッダで、属性語（`8013h`）はそのままですが名前欄はコードで潰れています。
  INIT が「鳳」を上に展開して、はじめてヘッダが `CON` と言う。だからヘッダは
  INIT の**あと**に読みます。属性のビット0（標準入力装置）でも CON を主張できる
  ようにしました——DOS が実際に見ているのはそっちです。
* **SPACE の仕事は `INT 28h` でやります。** 「鳳」は SPACE を受け取るとフラグを
  立てて帰るだけで、読みを引いて仮想鍵盤を描くのは DOS のアイドル割り込みの中。
  DOS は「文字が待っているか」（`AH=0Bh`）の答えが「いいえ」のときにこれを上げる
  ので、こちらもそうしました。これがないと SPACE は何も起こしません。
* **`AH=13h` には読む向きがあります。**「鳳」は窓を出す前に下にある行を読んで
  しまっておき、閉じるときに書き戻す。読めないと窓が開いたきりになります。

なお「鳳」は既定で **ATOK6 の API を `INT 6Fh` でエミュレート**します（`/a` で切れる）。
JW_CAD の検出テーブルにも `FP$ATOK6`＋`int 6f` があるので、デバイス名さえ合えば
JW_CAD 側の自動 on/off もそのまま噛み合うはずです。

### 辞書は SKK から作りました

「鳳」は `smsrom.dic`（ローマ字）`smsrea.dic`（読み）`smsdic.dic`（単漢字）が
ないと組み込まれません。本来は「風」の辞書を付属の `convdic.exe` で変換して作る
ものですが、「風」の辞書はもう落とせません。形式のほうは `DICTOOL.DOC` と
`CONVDIC.C` に二重に書き残されていて、実物の探索コード（`search_rea2`）でも
確かめられるので、語彙さえあれば作れます——`tools/mksmsdic.py` が SKK の公開辞書
から作ります。「鳳」は単漢字 FEP なので、使えるのは一文字の候補だけです。

## 辞書のこと

`SKK-JISYO.L` は SKK の公開辞書で、**GPL v2 以降**です。プログラム（このリポジトリの
C++）とは別々の著作物で、リンクもされず、実行時に読まれるだけのデータなので同梱は
集合著作物にあたります——が、辞書そのものは GPL のままです。差し替えたいときは
`--dict` で別のファイルを渡せます（`SKK-JISYO.M` なら 144 KB）。

形式は `読み /候補/候補/` の 1 行 1 項目で、送りありの項目（読みがローマ字で終わる）
は使っていません。EUC-JP から Shift-JIS への変換は表ではなく算術です（JIS X 0208 の
区と点の詰め方が違うだけ）。JIS X 0208 の 6,879 字すべてで Python の codecs と
突き合わせて確かめてあります。

## ホスト側の FEP も残してあります

本物の FEP が動くようになった今も、変換を**このエミュレータ自身が FEP として**
やる道は残してあります（`src/ime.cpp`、`ime on` で切り替え）。ローマ字→かな→
（SKK 辞書で）漢字、変換窓は画面の一番下の行。アプリケーションから見れば FEP は
機械の一部で、呼ぶものでも見えるものでもないので、ホスト側に置いても嘘には
なりません。そして同じ変換エンジンが、8086 を持たない C 移植（jwcad_dos_wasm）
でもそのまま要ります——あちらには「鳳」を走らせる 8086 がありません。
